# Strategy-data agent contract

## Research-backed system strategies

Before adding, retaining, rewriting, renaming, or changing Need associations for a system-authored strategy, read and follow `docs/system-strategy-evidence-standard.md` and `docs/content-evidence-review.md`.

A system strategy must clear a high direct-evidence threshold. Prefer high-quality systematic reviews/meta-analyses, evidence-based guidelines, or well-designed controlled human studies that evaluate the same action, or a substantially equivalent intervention, for an outcome relevant to the card.

Do not use mechanism-only papers, theoretical reviews, correlational evidence, uncontrolled pre/post studies, small pilots, adjacent interventions, or deductions from Need-level literature as the sole support for a production system strategy. If evidence is questionable or indirect, omit the strategy rather than filling the deck.

Keep card instructions inside the evidence. Do not invent unsupported duration, frequency, sequence, ratios, thresholds, or stronger outcomes than the source establishes.

Every research-backed system strategy must include one best supporting scholarly source and render through the standardized **`Supporting source ↗`** provenance link. Authoritative public-service cards may instead use an `official-resource` source.

These rules do not apply to genuine user-submitted strategy wording. Preserve user strategy text and provenance according to the repository's protected-user-content rules.

Research-facing production changes still require explicit complete-package approval before implementation.
